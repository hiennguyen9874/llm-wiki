Step-Audio-EditX is stepfun-ai's open-source 3B-parameter LLM-based audio model for iterative expressive audio editing — emotion, speaking style, and paralinguistics — with robust zero-shot text-to-speech cloning, built as a dual-codebook tokenizer plus audio LLM plus flow-matching decoder and released with inference code, model weights, and GRPO training code (**Reported**).[^step-audio-editx-readme]

## Model identity and release

- Name is Step-Audio-EditX; publisher is stepfun-ai (`github.com/stepfun-ai/Step-Audio-EditX`); technical report is `yan2025stepaudioeditxtechnicalreport`, titled `Step-Audio-EditX Technical Report` by Chao Yan, Boyong Wu, Peng Yang, Pengfei Tan, Guoqiang Hu, Yuxin Zhang, Xiangyu Zhang, Fei Tian, Xuerui Yang, Xiangyu Zhang, Daxin Jiang, and Gang Yu, year 2025, `eprint 2511.03601`, `primaryClass cs.CL`, `https://arxiv.org/abs/2511.03601` (**Reported**).[^step-audio-editx-readme]
- Released checkpoints are Step-Audio-EditX, Step-Audio-EditX-AWQ-4bit (also listed as Step-Audio-EditX-Int4 in the open-source plan), and Step-Audio-Tokenizer, each mirrored on Hugging Face (`stepfun-ai/*`) and ModelScope (`stepfun-ai/*`); a Hugging Face Space playground, web demo page, StepFun Audio Studio (needs a StepFun Open Platform API key), and a separate Step-Audio-Edit-Benchmark repository are linked (**Reported**).[^step-audio-editx-readme]
- Release timeline in the source News section runs Nov 06 2025 (technical report) through Jan 23 2026 (vLLM training/inference support, GRPO training code, expanded paralinguistic tags), with intermediate releases for the demo, optimized inference code and weights, a polyphonic-pronunciation version, the benchmark, and Japanese/Korean support (**Reported**).[^step-audio-editx-readme]
- Code in the repository is licensed Apache 2.0; no weight-specific license is stated in the captured source, and the source carries a usage disclaimer against unauthorized voice cloning, identity impersonation, fraud, and deepfakes, with compliance left to the user and misuse disclaimed by the developers (**Reported**, with the missing weight-license qualifier **Synthesis**).[^step-audio-editx-readme]

## Architecture and training

- Three primary components: a dual-codebook audio tokenizer converting reference/input audio into discrete tokens, an audio LLM generating dual-codebook token sequences, and an audio decoder converting predicted token sequences back to waveforms with a flow-matching approach (**Reported**).[^step-audio-editx-readme]
- The source states iterative emotion/style control leverages large-margin data during SFT and PPO training; the open-source plan marks GRPO training code released and SFT/PPO training code still pending at capture time (**Reported**).[^step-audio-editx-readme]
- Acknowledged upstream code/data sources are CosyVoice, transformers, FunASR, NVSpeech (Emilia-NV dataset), and vLLM; no shared-checkpoint or training-data claim beyond this acknowledgment is asserted (**Reported**).[^step-audio-editx-readme]

## Controllability

- Zero-shot TTS cloning covers Mandarin, English, Sichuanese, and Cantonese, with Japanese and Korean added Nov 28 2025; dialects and the added languages are selected with a tag before the text (`[Sichuanese]`, `[Cantonese]`, `[Japanese]`, `[Korean]`) (**Reported**).[^step-audio-editx-readme]
- Polyphonic pronunciation control works by replacing polyphonic characters with pinyin, e.g. `[我也想过过过儿过过的生活]` → `[我也想guo4guo4guo1儿guo4guo4的生活]` (**Reported**).[^step-audio-editx-readme]
- Emotion editing lists 14 tags (happy, angry, sad, fear, surprised, confusion, empathy, embarrass, excited, depressed, admiration, coldness, disgusted, humour); speaking-style editing lists 32 tags (serious, arrogant, child, older, girl, pure, sister, sweet, exaggerated, ethereal, whisper, generous, recite, act_coy, warm, shy, comfort, authority, chat, radio, soulful, gentle, story, vivid, program, news, advertising, roar, murmur, shout, deeply, loudly); the prose claims dozens of options with more on the way (**Reported**, with the tag counts **Observed** by static inspection).[^step-audio-editx-readme]
- Paralinguistic editing is described as precise control over 10 feature types in prose, while the Available Tags table enumerates 22 tags: `[sigh]`, `[inhale]`, `[laugh]`, `[chuckle]`, `[exhale]`, `[clears throat]`, `[snort]`, `[giggle]`, `[cough]`, `[breath]`, `[uhm]`, `[Confirmation-en]`, `[Surprise-oh/ah/wa/yo]`, `[Dissatisfaction-hnn]`, `[Question-ei/ah/en/yi/oh]`; the Jan 2026 news notes expanded tags including Cough, Crying, and Stress, and filler-word removal remains a pending feature (**Reported**).[^step-audio-editx-readme]
- Additional edit types demonstrated in `tts_infer.py` are `denoise` and `vad` (prompt text not needed) and `speed` with `faster`, `slower`, `more faster`, `more slower`; the Tips note recommends keeping audio under 30 seconds per inference for optimal performance (**Reported**).[^step-audio-editx-readme]

## Requirements, installation, and inference

- Requirements table (batch size 1): 3B parameters, 41.6 Hz sample-frequency setting, 12 GB optimal GPU memory with 16 GB recommended as safer; tested on a single L40S GPU under Linux with an NVIDIA CUDA GPU required; dependencies are Python >= 3.12, PyTorch >= 2.9.1, and CUDA Toolkit (**Reported**).[^step-audio-editx-readme]
- Installation is `git clone https://github.com/stepfun-ai/Step-Audio-EditX.git`, `cd Step-Audio-EditX`, `uv sync --refresh`, `source .venv/bin/activate`, then `git lfs install` plus cloning the Tokenizer, EditX, and AWQ-4bit models; a Dockerfile path (`docker build . -t step-audio-editx`, `docker run --rm --gpus all -v ... -p 7860:7860`) is also given (**Reported**).[^step-audio-editx-readme]
- CLI inference is `python3 tts_infer.py --model-path … --tokenizer-path … --prompt-text … --prompt-audio … [--generated-text …] --edit-type {clone, emotion, style, paralinguistic, denoise, vad, speed} [--edit-info …] --output-dir ./output`, with per-type examples (clone with prompt/generated text pair; emotion `fear`/`happy`; style `whisper` with more than one iteration recommended; paralinguistic tag insertion such as `[Uhm]`; speed `more faster`) and one-or-more per-iteration output waves (`*_edited_iterN.wav`) (**Reported**).[^step-audio-editx-readme]
- Web demo is `python app.py --model-path … --tokenizer-path … --model-source {auto, local, modelscope, huggingface}` with vLLM/CosyVoice memory options (`--gpu-memory-utilization` 0.5, `--max-model-len` 3072, `--enforce-eager` True, `--max-num-seqs` 1, `--dtype bfloat16`, `--quantization {awq, gptq, fp8}`, `--cosyvoice-dtype bfloat16`, `--no-cosyvoice-cuda-graph`, `--enable-auto-transcribe`); the memory guide estimates standard 12–15 GB, memory-efficient 6–8 GB, and AWQ 4-bit 8–10 GB, including a memory-efficient `app.py` example (**Reported**).[^step-audio-editx-readme]
- Optional AWQ 4-bit quantization runs `python quantization/awq_quantize.py --model_path path/to/Step-Audio-EditX`; details are deferred to `quantization/README.md` and training to `script/ReadMe.md`, neither of which is in `raw/` (**Reported**).[^step-audio-editx-readme]

## Performance and evaluation

- The source asserts Step-Audio-EditX outperforms MiniMax and Doubao in zero-shot cloning and emotion control, that one editing iteration improves emotion-controlled outputs of all three compared models with further gains over iterations, and that closed-source built-in voices gain emotion/style accuracy each round while paralinguistic reproduction after editing matches native paralinguistic synthesis (**Reported**).[^step-audio-editx-readme]
- The generalization table reports emotion/style accuracy (Iter0→Iter3, higher better) and paralinguistic scores (Iter0, sub-word replacement, Iter1) for MiniMax-2.6-hd, Doubao-Seed-TTS-2.0, GPT-4o-mini-TTS, and ElevenLabs-v2 in Chinese, English, and average rows; e.g. average emotion rises from 55.7–63.3 at Iter0 to 72.2–74.9 at Iter3, average style from 42.6–49.1 to 63.6–67.4, and paralinguistic from ~1.7–1.9 to ~2.9 after one edit (**Reported**, with the directional trend **Observed** by static inspection).[^step-audio-editx-readme]
- No evaluation protocol, metric definitions, sample sizes, hardware, uncertainty, or independent verification accompany the figures in this source; the benchmark repository and demo audio (remote `.webm` files) were linked but not fetched or listened to, and the architecture and emotion-eval figures (`assets/architechture.png`, `assets/emotion-eval.png`) were not visually inspected (**Synthesis**).[^step-audio-editx-readme]
