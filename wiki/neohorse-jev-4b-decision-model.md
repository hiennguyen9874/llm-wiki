# NeoHorse-Jev-4B Structured Decision Model

Synthesis: NeoHorse-Jev-4B is a TokenRhythm ~4B prefill-only decision model on NeoHorse-1-4B that returns Choice, Noul, or Score distributions over application-defined answers without autoregressive generation, with **reported** six-group text mean 77.70 and three-benchmark mean 83.26%, plus single-image decisions and native, vLLM, and SGLang serving[^neohorse-jev-4b-2026-09-24].

## Architecture and composition — observed

- Format from `model_manifest.json` / `config.json`: unified multimodal backbone plus independent decision pointer head, not a chat causal LM; backbone class `Qwen3_5Model` with `language_model` plus `visual` components; backbone BF16, head FP32, merge FP32; `head_dim` 256; `option_isolation: false`; `hybrid: true`; `temperature: 1.0`[^neohorse-jev-4b-2026-09-24].
- Backbone config **observed** in `backbone/config.json`: text tower 32 layers mixing `linear_attention` and `full_attention`, hidden 2560, vocab 248320, 262144 positions; vision tower depth 24, hidden 1024; vision token ids 248053–248057; language weights fine-tuned from `Qwen/Qwen3.5-4B` and repackaged by changing config and tensor-key prefixes without changing tensor values[^neohorse-jev-4b-2026-09-24].
- Complete bundle layout from README “Download” and “Installation” sections: `backbone/` (~9.08 GB unified language+vision safetensors plus index), `tokenizer/`, `pointer_head.safetensors` (~5.25 MB separate head), `model_manifest.json`, `dist/` wheel plus `package/` source, `example_request.json`, and `vision/` image examples; vLLM and SGLang adapters live only in the GitHub `jev/infer/` tree, so all three paths still require the complete downloaded model directory including the separate head[^neohorse-jev-4b-2026-09-24].
- Recorded native environment from `environment.json` and `DEPLOYMENT.md`: Linux, Python 3.12, PyTorch 2.8.0, Transformers 5.17.0, Triton 3.7.1, `flash-linear-attention` 0.5.2, CUDA GPU with BF16 (recorded GPU NVIDIA H20, CUDA 12.8); HTTP/serve extras pin `fastapi==0.141.1`, `uvicorn==0.53.0`, `starlette==1.6.0`, `httpx==0.28.1`, `pillow==12.3.0`[^neohorse-jev-4b-2026-09-24].

## Text interface and serving — observed

- Contract: supply `state` plus a `questions` map with application-defined keys; per question `type` plus `instructions` plus `criteria` where required — Choice takes an ordered candidate dictionary, Noul takes an optional yes/no question and returns `P(true)`, Score takes lowest-to-highest rating levels indexed from `0` and returns a level distribution plus fractional expected rating[^neohorse-jev-4b-2026-09-24].
- Multi-question text requests return one answer per key (up to 16 questions); code comment in `engine.py::DecisionEngine` notes hybrid execution repeats the state in each independent question row, and the docs state multiple questions in one request do not imply a single shared forward pass[^neohorse-jev-4b-2026-09-24].
- Three serving paths from README “Deployment” and `DEPLOYMENT.md`: vLLM 0.28.0 (`infer/vllm/launch.py` plus `infer/vllm/infer.py`), SGLang 0.5.17 (`infer/sglang/launch.py` plus `infer/sglang/infer.py`), and native `neohorse_decision` Python (`DecisionEngine`), CLI (`neohorse-decision predict`), and HTTP service (`neohorse-decision serve`); vLLM/SGLang need a separate cloned `jev/` directory and existing backend environment, while native installs the bundled wheel with `--no-deps` into an already prepared ML environment or installs `./package` from source[^neohorse-jev-4b-2026-09-24].
- HTTP endpoints **observed** in `package/src/neohorse_decision/server.py`: `POST /v1/decision` (native `{model, answers, input_tokens}` plus `image_tokens` for images) and `POST /v1/systemone` (`{model, answers, usage}` with `usage.input_tokens/output_tokens` plus `usage.image_tokens`); `GET /health` reports readiness and `input_modalities`; both decision endpoints share weights, encoding, and probabilities; there is no `/v1/models`[^neohorse-jev-4b-2026-09-24].
- Accepted model names **observed** in `package/src/neohorse_decision/systemone.py`: `NeoHorse-Jev-4B`, `TokenRhythm/NeoHorse-Jev-4B`, `neohorse-jev`, and `JEV` case variants; responses use canonical `NeoHorse-Jev-4B`; the module docstring states this is a System One wire adapter, not official Jev calibration or billing[^neohorse-jev-4b-2026-09-24].
- Confidence semantics from `DEPLOYMENT.md` §5 and `systemone.py::with_confidence`: `confidence` is a local distribution statistic, not a calibrated P(correct) — Choice `(max(p)-1/K)/(1-1/K)`, Score `1-sum p_i*|i-argmax|/(L-1)`, clamped to `[0,1]` with single-candidate Choice returning `1`; native `DecisionEngine.predict` does not return `confidence` while both HTTP endpoints add it; native Noul retains yes/no `probabilities` while the System One shape strips Noul answers to `{type, noul}`; headers are `X-NeoHorse-Confidence: local-distribution-statistic-v1` and, on System One only, `X-NeoHorse-Usage: local-tokenizer-not-jev-billing`[^neohorse-jev-4b-2026-09-24].
- Token accounting from `DEPLOYMENT.md` §5: `input_tokens` counts encoded inputs with shared state counted once, not GPU-expanded branch tokens; `output_tokens` is the local tokenizer count of the response JSON, not generation; for images `input_tokens` already includes image tokens plus vision markers, so do not add `image_tokens` again; text responses carry no `image_tokens`[^neohorse-jev-4b-2026-09-24].
- Deployment limits **observed** in `engine.py`, `server.py`, `vision.py`, and `DEPLOYMENT.md` §7: text `state` 2,048 tokens, each question branch 8,192 tokens, ≤16 questions per text request, ≤32,768 total expanded tokens, text body 1 MiB (image bodies 8 MiB with non-image JSON fields still 1 MiB), System One Score 2–10 levels; over-limit inputs are rejected without silent truncation; the runtime does not schedule GPUs across a cluster[^neohorse-jev-4b-2026-09-24].
- Concurrency and security **observed**: one serialized GPU worker via non-blocking locks; busy text/image workers return `429` on `/v1/decision` and `529` on `/v1/systemone` with `Retry-After: 1`; no separate quota limiter, so gate concurrency externally; service binds `127.0.0.1` by default with optional `NEOHORSE_API_KEY` Bearer auth and a TLS gateway for external access; image decode in `image_input.py` accepts only inline base64 PNG/JPEG/WebP data URLs and rejects URLs, paths, MIME mismatches, animation, and decompression bombs[^neohorse-jev-4b-2026-09-24].
- Error mapping from `DEPLOYMENT.md` §7: `401` bad bearer, `413` body/field oversize, `422` invalid JSON/fields, unknown model, or unsupported image/dimension/token/multi-question/animation constraint, `429/529` busy worker[^neohorse-jev-4b-2026-09-24].

## Vision — observed

- One static image plus text plus exactly one Noul, Choice, or Score question per image request; HTTP uses a single top-level `image` base64 data URL (omit when absent, never `null`); local API is `VisionDecisionEngine.predict(request, pil_image)` with RGB conversion; `vision/example.py` and `vision/http_example.py` are the bundled local and HTTP clients[^neohorse-jev-4b-2026-09-24].
- Image bounds from docs and code: decoded file ≤4 MiB, source ≤4 megapixels, preprocessing area budget 65,536–1,048,576 pixels, image tokens ≤1,024, total encoded image request ≤12,288 tokens; multiple images, video, and audio are not supported; text and image requests share the backbone, head, and GPU lock with no dynamic batching; `vision.py` resets `rope_deltas` per request and raises on non-finite probabilities[^neohorse-jev-4b-2026-09-24].
- Verification scope from `vision/verification.json`: status `PASS` for local connectivity and text parity, explicitly not multimodal benchmark validation — 5/5 color/position smoke cases, 16 text reference requests with 18 wrapper questions at `0.0` max probability difference on identical single-question requests, and a BF16 split-vs-batch difference `0.00418` recorded separately rather than treated as vision drift; peak allocation ~9.83 GB in that run[^neohorse-jev-4b-2026-09-24].

## Reported benchmarks

- Six-group text aggregate (equal-weight mean of displayed groups, computed before rounding; only models with all six groups are ranked): NeoHorse-Jev-4B **77.70**, reported highest among the four complete open-weight entries — JevBench 75.73 (second), Kev 81.92 (first), OpenJev text 58.74 (second), Nimble 87.23 (first), VitaminC 77.13, MASSIVE-en 85.43 (second) — versus Open-Jev-9B 75.67, Kev-4B 74.25, and Laya English 58.24; NeoHorse-Jev-4B uses vLLM results for JevBench/Kev/OpenJev in that table while Nimble/VitaminC/MASSIVE retain fixed-subset results[^neohorse-jev-4b-2026-09-24].
- Three-benchmark mean (Nimble, VitaminC, MASSIVE weighted equally over 1,231 examples, unrounded accuracies): NeoHorse-Jev-4B **83.26%**, **reported** 11.50 points above NeoHorse-1-4B (71.76%) — versus Kev-4B 78.53, Open-Jev-9B 77.88, Laya English 64.08, and Laya Typed 64.22; recomputing from two-decimal components can differ by 0.01[^neohorse-jev-4b-2026-09-24].
- Subset protocol for those three: IDs frozen before comparison with reference answers for scoring only; upstream VitaminC/MASSIVE sampling seed `20260918` with complete case groups; local selection caps 384-token state, 2,048-token packed decisions, ≤26 candidates (base letter-logit prompt 4,096); Nimble 282/324 after length and whole-group filtering (116 Choice, 112 Noul, 54 Score with exact rating-level matches), VitaminC-dev 599 three-way evidence/claim cases, MASSIVE-en 350 English cases across 18 scenarios (not intent/slot or multilingual evaluation)[^neohorse-jev-4b-2026-09-24].
- JevBench public 231: per-example accuracy 75.32% with 100% valid format; family-macro 75.73; family pattern is strongest on ambiguous, extraction, adequacy-second, and routing/tool/judge-hard/policy ties, weakest on temporal-numeric (0.00), probability (40.00), tradeoff (33.33), and trap-second (87.50); per-family example counts range from 5 (routing_hard) to 24 (extraction/intent)[^neohorse-jev-4b-2026-09-24].

- OpenJev static text (19-task equal-weight mean with MNLI splits averaged first): NeoHorse-Jev-4B leads SciTail (87.02) and MNLI-mismatched (89.46) with second place on ANLI/WANLI/control, MNLI-matched, and most rerank tasks (ARC, Winogrande, GSM8K-MC, HellaSwag, MMLU), while Open-Jev-9B sweeps the rerank block; frozen-candidate GSM8K (200 examples) `nli_rerank@4` 94.50 versus Open-Jev-9B 95.00 against a shared pool with 93.00 greedy, 93.50 majority-vote, and 97.00 oracle@4 properties[^neohorse-jev-4b-2026-09-24].

## Limitations and trust boundaries

- Decisions can be wrong despite valid structure and normalized probabilities; missing evidence, candidate descriptions and order, and domain shifts all affect results[^neohorse-jev-4b-2026-09-24].
- NLL, Brier, and ECE calibration results are **reported** as not yet available; validate thresholds on independent data and treat `confidence` as an uncalibrated local statistic per §5 above[^neohorse-jev-4b-2026-09-24].
- Scope claims to measured evidence: comprehensive multilingual, long-input, and cross-question computational-isolation evaluations are not available, and no latency, GPU-memory, or cost comparison under a common timing protocol is supplied; applications retain tool permissions, business rules, and action validation[^neohorse-jev-4b-2026-09-24].
