# ai-memory harness integrations, install flow and CLI

ai-memory integrates with more than twenty agent harnesses so they share one memory; each integration is MCP registration, lifecycle hooks, or both.[^readme] The README's support matrix lists about 40 rows and says every row is checked by CI (**Reported**).[^readme][^support-matrix]

Evidence class: **Observed** for the CLI and docs; CI claims are **Reported**; nothing executed.

## Support tiers (examples from the README matrix)

- **Supported (hooks + MCP):** Claude Code, Codex, Command Code, Devin CLI, OpenCode (V1/V2 auto-detected), Cursor, Gemini CLI, Oh My Pi, Pi, OpenClaw, Antigravity CLI, Grok Build CLI, Zero, ZCode, Kimi Code, Kiro CLI, GitHub Copilot CLI, Factory Droid, Meta Muse Code, IBM Bob, Qwen Code, Qoder, Hermes Agent, GrizzyBot.[^readme]
- **Hooks-only:** Pool, CodeBuddy Code. **MCP-only:** Claude Desktop, Swival CLI, VS Code Copilot, Zed, FreeBuff, Prime Agent. **Managed-only:** Crush. **Hooks + MCP:** DeepSeek Harness, Cline CLI. Native Windows is *Experimental*; Windows via WSL2 is supported.[^readme]
- Full per-agent notes live in the support matrix and per-client MCP notes.[^support-matrix][^mcp-install]

## Three integration shapes

1. Staged POSIX/PowerShell script bundles under `hooks/<agent>/` (15 dirs plus `_lib.sh`).
2. Generated TypeScript extensions (OpenCode v1/v2, OMP, Pi, OpenClaw).
3. Native exec-form `ai-memory hook` commands (Muse, Droid, Qwen, Qoder, ZCode, Zero, Kimi, Kiro, Copilot CLI, IBM Bob, Hermes, DSH bridge).

Marketplace plugins for Claude Code and Codex are generated by `render-plugins` and delegate wholly to `ai-memory hook`.[^plugins-readme] (Shapes: **Observed** by directory listing and delegated reading.)

## Install and wiring flow

- Native install: `install.sh` (checksum-verified) then `ai-memory setup`, which creates the data dir with an owner-only bearer token, starts a per-user service, wires MCP/hooks/Agent Skills for detected agents, and runs a self-check; `--plan` previews, `--web` shows a browser plan, `--yes` skips the prompt, and re-runs are idempotent.[^readme]
- `install-hooks` prints a plan unless `--apply`; `install-mcp` writes or prints client snippets, and token-file installs never write the bearer into harness config (the `mcp-bridge` stdio bridge reads it from the data dir).[^readme][^mcp-install]
- **Preferred launch:** `ai-memory run <harness>` auto-installs missing hooks/MCP on first run per harness/version/install location, wires the project scope, and adds cross-harness session continuity (see [Managed workstreams](ai-memory-managed-workstreams.md)); opt out with `--no-autowire` or `AI_MEMORY_RUN_AUTOWIRE=false`.[^readme]
- `uninstall --apply` removes only what ai-memory installed; installers write timestamped backups next to touched files.[^readme]
- Docker quick-start has **no authentication** (container never runs `init`; loopback-only publish).[^readme]
