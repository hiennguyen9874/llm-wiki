WhisperLiveKit (WLK) by Quentin Fuxa is an Apache-2.0, self-hosted, ultra-low-latency speech-to-text pipeline that replaces naive per-chunk Whisper batching with simultaneous-speech policies, VAD/VAC-gated streaming, pluggable ASR backends, optional diarization and 200-language translation, and OpenAI/Deepgram-compatible plus native WebSocket serving for multiple concurrent users (**Reported**).[^wlk-readme]

## Identity and rationale

- Purpose: realtime transcription, translation, and speaker-attributed capture for meetings, accessibility, podcasts/video, and support calls; installable from PyPI as `whisperlivekit` with Python 3.11–3.13 support (**Reported**).[^wlk-readme]
- Naive-chunk argument: Whisper is designed for complete utterances, so small-segment inference loses context, cuts words mid-syllable, and degrades quality; WLK instead uses Simul-Whisper/SimulStreaming with AlignAtt policy, WhisperStreaming with LocalAgreement policy, plus NLLW/NLLB translation, Streaming Sortformer diarization, Qwen3-ASR-causal encoding, and AlignAtt4LLM translation-gating research (**Reported**).[^wlk-readme]
- Architecture note: one backend serves multiple concurrent users, and voice activity detection reduces overhead when no voice is present (**Reported**).[^wlk-readme]
- Companion weights named in the source: `qfuxa/qwen3-asr-0.6b-streaming` on Hugging Face for the causal Qwen3 tower (**Reported**).[^wlk-readme]

## Install and CLI

- Install fence: `pip install whisperlivekit`, then `wlk --model base --language en` starts the server with the demo at `http://localhost:8000` (**Reported**).[^wlk-readme]
- CLI surface: `wlk run whisper:tiny` (auto-pull plus server), `wlk transcribe meeting.wav` (file without server), `wlk transcribe --format srt podcast.mp3 -o podcast.srt`, `wlk models`, `wlk pull large-v3`, `wlk rm large-v3`, `wlk bench` with backend/language/JSON variants (**Reported**).[^wlk-readme]
- File-transcription and subtitle fences above are transcribed, not executed (**Synthesis**).[^wlk-readme]

## Serving APIs and per-session parameters

- Compatibility subsets: OpenAI-compatible REST (`POST /v1/audio/transcriptions`, usable with the OpenAI Python SDK against `http://localhost:8000/v1`), Deepgram-compatible WebSocket (SDK setup deferred to `docs/API.md`), and native realtime WebSocket at `ws://localhost:8000/asr`; full reference deferred to `docs/API.md` and a native SwiftUI macOS client lives under `macos/WhisperLiveKitMac` (**Reported**).[^wlk-readme]
- Per-session WebSocket query parameters: `language` (e.g. `?language=fr`; one shared engine serves mixed-language sessions), `target_language` (e.g. `?target_language=de`; server must run with `--target-language`), `context` (terminology/phrase-list conditioning for Whisper-family and SimulStreaming backends), `mode` (`diff` incremental snapshot protocol, experimental for custom clients via `diff_protocol.py`, versus `full` used by the bundled UI), and `token` (API token when `--api-token` is set, also accepted as `Authorization: Bearer`) (**Reported**).[^wlk-readme]

## Streaming policies and backend selector

- `--backend-policy`: `1`/`simulstreaming` (AlignAtt SimulStreaming, default) versus `2`/`localagreement` (LocalAgreement policy) (**Reported**).[^wlk-readme]
- `--backend` selector: `auto` picks MLX on macOS when installed, else Faster-Whisper, else vanilla Whisper; explicit options are `mlx-whisper`, `faster-whisper`, `whisper`, `openai-api` (LocalAgreement only), `funasr`, `voxtral-mlx` (Apple Silicon), `voxtral` (HuggingFace), `qwen3-vllm`, `qwen3-vllm-metal` (Apple Silicon), `qwen3-streaming` (HF, CUDA/MPS/CPU), and `canary` (NeMo, CUDA/CPU, LocalAgreement only) (**Reported**).[^wlk-readme]
- SimulStreaming knobs: `--disable-fast-encoder`, `--custom-alignment-heads` (extract via `scripts/determine_alignment_heads.py` when `--model-dir` is used), `--frame-threshold` 25 (lower faster, higher more accurate), `--beams` 1, `--decoder` auto (`beam`/`greedy`), `--audio-max-len` 30.0 s, `--audio-min-len` 0.0 s, `--cif-ckpt-path`, `--never-fire`, `--init-prompt`, `--static-init-prompt`, `--max-context-tokens` usually 448 (**Reported**).[^wlk-readme]
- WhisperStreaming knobs: `--confidence-validation` false, `--buffer_trimming` `segment` (or `sentence`) (**Reported**).[^wlk-readme]

## Optional dependencies and install profiles

- Extras matrix (representative): `mlx-whisper`, `funasr`, `voxtral-mlx`, `cpu`, `cu129`, `translation`, `sentence_tokenizer`, `voxtral-hf`, `qwen3-vllm`, `qwen3-streaming`, `qwen3-vllm-metal` (requires the official vLLM Metal install first), `diarization-sortformer`, legacy `diarization-diart`, and `canary`, each installable via `uv sync --extra <name>` or `pip install -e ".[<name>]"` (**Reported**).[^wlk-readme]
- Documented GPU profiles: A Sortformer diarization (`cu129` plus `diarization-sortformer`); B Voxtral HF plus translation (`cu129` plus `voxtral-hf` plus `translation`); C Qwen3-ASR vLLM (`qwen3-vllm` alone) (**Reported**).[^wlk-readme]
- Conflict rules: `qwen3-vllm` uses the vLLM CUDA wheel stack and must live in a separate environment from `cu129`; several heavy extras (`voxtral-hf`, `qwen3-vllm-metal`, vLLM stacks) intentionally conflict and need separate environments with `[tool.uv].conflicts` in `pyproject.toml` authoritative; `canary` conflicts with `voxtral-hf` and `qwen3-vllm-metal` but is compatible with `diarization-sortformer` since both pull `nemo-toolkit[asr]` (**Reported**).[^wlk-readme]
- Diart is not recommended and is limited to Python 3.11/3.12 because Diart 0.9.2 requires NumPy below 2; Sortformer is the path for Python 3.13 (**Reported**).[^wlk-readme]

## Backend notes: Voxtral, FunASR, Qwen3, Canary

- Voxtral: Mistral AI Voxtral Mini 4B with 100+ languages and automatic detection; per-chunk detection is stated to be more reliable than Whisper `--language auto` and not English-biased; uses its own streaming policy, not LocalAgreement or SimulStreaming; Apple Silicon fence is `.[voxtral-mlx]` plus `wlk --backend voxtral-mlx`, Linux/GPU fence is transformers plus torch with `--backend voxtral`; numbers deferred to `BENCHMARK.md` (**Reported**).[^wlk-readme]
- FunASR/SenseVoiceSmall: runs through WLK LocalAgreement plus VAC/VAD; explicit `--backend funasr --language auto` fence, or a verified local snapshot via `--model_dir` without executing remote model code; covered languages are Mandarin (`zh`), Cantonese (`yue`), English, Japanese, Korean, plus auto; selecting it with the default policy auto-switches to LocalAgreement; it does not support `--direct-english-translation`, WLK keeps voice-activity control instead of FunASR internal VAD, and the contract covers only SenseVoiceSmall, not arbitrary FunASR models under its model license (**Reported**).[^wlk-readme]
- Qwen3-streaming (HF Transformers, no vLLM): bounded-recompute audio cache where the pretrained tower re-encodes only a local window (default 12 s) per update, cached audio embeddings are append-only, and text commits by a stable-prefix rule; runs on CUDA/MPS/CPU; explicit `--language` is required because auto-detection switches mid-stream on accented audio; word timestamps are interpolated estimates around 1 s precision for lines and diarization alignment while exact timing needs `--backend qwen3-vllm` with ForcedAligner; decode pacing self-adjusts to hardware and slower-than-realtime GPUs get slower cadence instead of lag, so plan one realtime session per GPU; validated defaults are 12 s left context with ~15 s segments and `--qwen3-streaming-*` knobs in `--help` (**Reported**).[^wlk-readme]
- Qwen3 causal mode (minimum per-chunk compute): append-only causal-KV encoder encodes each ~2 s block exactly once with bounded memory (15 s window plus sentence-boundary resets) and stream-length-constant compute; fence adds `--qwen3-streaming-audio-backend causal --qwen3-streaming-tower-checkpoint qfuxa/qwen3-asr-0.6b-streaming` with automatic download; runtime, tests, experiments, benchmarks, and figures live in the Qwen3-ASR-causal repo consumed via `third_party/qwen3-asr-causal`, WLK keeping only wiring and flags; use causal for many concurrent streams, energy-constrained serving, or unbounded sessions and the windowed default for best accuracy; English-only for now with WER/RTF in the Qwen3-ASR-causal repo (**Reported**).[^wlk-readme]
- Experimental Qwen3 vLLM paths: Metal `qwen3-vllm-metal` with `--qwen3-vllm-metal-audio-backend causal` keeps a rolling MLX decoder KV over the prompt-plus-audio prefix and replays only new audio embeddings, prompt tail, and prior-hypothesis draft; it passed local short-form smoke tests but stays experimental with `qwen3-streaming` causal as the validated production stack; CUDA `qwen3-vllm` with `--qwen3-vllm-audio-backend causal --qwen3-vllm-causal-decoder-backend vllm-live` needs `WLK_QWEN3_VLLM_LIVE_MULTIPROCESSING=1`, keeps vLLM ForcedAligner timestamps, offers conservative `vllm-text` fallback (prefix caching, one text request per chunk) and `append-kv`/`rolling` aliases for the HF decoder path; standard `qwen3-vllm` remains the accuracy choice until the causal quality gate is fixed (**Reported**).[^wlk-readme]
- Canary (NeMo, CUDA/CPU): NVIDIA Canary-1b-v2 1B model over 25 European languages with native word timestamps, streaming through LocalAgreement; auto detection uses NeMo AmberNet and locks in once enough audio accumulates; GPU strongly recommended (CPU works via `scripts/smoke_canary.py` but is slow for 1B params; Apple Silicon restore path uses CPU, no MPS placement); NeMo is a heavy stack; supported Python is 3.11–3.13 with `nemo-toolkit[asr]>=3.0,<4`; explicit `--language` skips detection; tune with `--canary-lid-min-sec` 2.0 s and `--canary-lid-min-conf` 0.5; Canary-1b-v2 is CC-BY-4.0 with separate NGC terms for the AmberNet language-ID model (**Reported**).[^wlk-readme]

## Translation, VAD/VAC, and diarization

- Translation: `--target-language` translates through NLLW across 200 languages (language list in `docs/supported_languages.md`), while `--direct-english-translation` makes the STT model output English directly; `--translation-backend` is `nllb` (in-process, CPU-friendly) or `alignatt` (streaming LLM translation through an Alignatt4LLM sidecar with attention-gated append-only commits, see `docs/translation-alignatt.md`); NLLB knobs are `--nllb-backend` (`transformers`/`ctranslate2`) and `--nllb-size` (`600M`/`1.3B`) (**Reported**).[^wlk-readme]
- Voice-activity and segmentation: `--no-vac` and `--no-vad` both disable their stage and are marked not advised; `--pause-segmentation-seconds` 5.0 s creates a stable transcript boundary on longer VAD pauses (`0` disables); `--asr-coalesce-min-s` 0 defers ASR calls until that much new audio accrues to trade update cadence for fewer encoder passes (`0` disables) (**Reported**).[^wlk-readme]
- Diarization: `--diarization` enables speaker identification with `--diarization-backend diart` or `sortformer` (default `sortformer`); Sortformer knobs are `--sortformer-model-path` (local `.nemo`, directory with one `.nemo`, or NeMo/HF ID) and `--sortformer-max-speakers` 1–4; the max-speakers value is an assertion about the audio rather than estimation — only the first N arrival-ordered channels are kept, extra speakers can be misattributed, and although Sortformer emits independent overlapping activity WLK resolves each frame and ASR token to one speaker with no simultaneous-speaker output (**Reported**).[^wlk-readme]
- Diart prerequisites and caveats: accept the `pyannote/segmentation`, `pyannote/segmentation-3.0`, and `pyannote/embedding` user conditions then `huggingface-cli login`; model knobs are `--segmentation-model` (`pyannote/segmentation-3.0`) and `--embedding-model` (`pyannote/embedding`); `--disable-punctuation-split` is flagged not functional in 0.2.15/0.2.16 (issue #214) (**Reported**).[^wlk-readme]

## Core model, language, server, and LoRA parameters

- `--model` default `small` (sizes and recommendations in `docs/default_and_custom_models.md`); `--model-path` accepts a local `.pt`/directory or HF repo ID and overrides `--model`; `--language` default `auto` with a tokenizer language list at `whisperlivekit/whisper/tokenizer.py`, noting auto-detection biases toward English; LoRA adapters via `--lora-path` (path or HF ID such as `qfuxa/whisper-base-french-lora`) work only with the native Whisper backend (**Reported**).[^wlk-readme]
- Server: `--host localhost`, `--port 8000`, `--warmup-file jfk.wav`, SSL via `--ssl-certfile`/`--ssl-keyfile`, reverse-proxy trust via `--forwarded-allow-ips`, CORS via `--cors-origins` (empty disables, `*` allows all), raw s16le PCM input with FFmpeg bypass via `--pcm-input` (frontend switches to AudioWorklet instead of MediaRecorder) (**Reported**).[^wlk-readme]

## Python API, frontend, deployment, and Docker

- Python pattern: share one `TranscriptionEngine(model_size="medium", diarization=True, lan="en")` created in FastAPI lifespan, then per-connection `AudioProcessor(transcription_engine=...)` with `create_tasks()`, a results generator forwarded by `send_json`, `websocket.accept()`, a `receive_bytes()` loop into `process_audio()`, and a `ready_to_stop` close message; fuller example deferred to `basic_server.py` (**Reported**).[^wlk-readme]
- Frontend: bundled HTML/JavaScript at `whisperlivekit/web/live_transcription.html`, also importable via `get_inline_ui_html()` (**Reported**).[^wlk-readme]
- Production recipe: `pip install uvicorn gunicorn` then `gunicorn -k uvicorn.workers.UvicornWorker -w 4 your_app:app`; host a customized copy of the HTML example with the correct WebSocket URL; Nginx reverse proxy with `Upgrade`/`Connection`/`Host` forwarding; use `wss://` for secure deployments with the SSL parameters above (**Reported**).[^wlk-readme]
- Docker: GPU `docker build -t wlk .` plus `docker run --gpus all -p 8000:8000 --name wlk wlk`; CPU `docker build -f Dockerfile.cpu -t wlk --build-arg EXTRAS="cpu" .`; custom runs append WLK flags (example `--model large-v3 --language fr`); Compose profiles are `wlk-gpu-sortformer`, `wlk-gpu-voxtral`, and `wlk-cpu` with `docker compose up --build <service>`; `EXTRAS` build-arg examples are `cu129,diarization-sortformer`, `cu129,voxtral-hf,translation`, and `cpu,diarization-diart,translation`; HF cache plus token ride on a named volume and `HF_TKN_FILE` (default `./token`) (**Reported**).[^wlk-readme]
- Chrome extension for capturing web-page audio lives under `chrome-extension` (**Reported**).[^wlk-readme]

## Relationships

- Uses [Faster-Whisper](faster-whisper.md): WLK's `faster-whisper` backend (and the non-MLX pick under `auto`) runs this CTranslate2 Whisper runtime with batched inference and quantization options; consult that page for benchmarks, VAD filtering, and model conversion (**Synthesis**).[^wlk-readme]
- Uses [Canary-1b-v2](canary-1b-v2.md): WLK's `canary` backend is the NeMo streaming integration of that 25-language model with AmberNet auto-detection and native word timestamps; consult that page for language coverage and FLEURS/CoVoST2/MLS/Open-ASR-Leaderboard figures (**Synthesis**).[^wlk-readme]
- Uses [Qwen3-ASR family](qwen3-asr-family.md): WLK's `qwen3-streaming`, `qwen3-vllm`, and `qwen3-vllm-metal` backends (windowed plus causal) are the streaming deployment of that family; consult that page for checkpoint, language, accuracy, and aligner behavior (**Synthesis**).[^wlk-readme]
- Uses [SenseVoiceSmall GGUF](sensevoice-small-gguf.md): WLK's `funasr` backend covers the same SenseVoiceSmall model (Mandarin, Cantonese, English, Japanese, Korean) through LocalAgreement plus WLK-side VAC/VAD; consult that page for the audio.cpp packaging while this page governs the WLK server integration (**Synthesis**).[^wlk-readme]
- Uses [Sortformer Diarizer 4spk v1](diar-sortformer-4spk-v1.md), [Streaming Sortformer Diarizer 4spk v2](diar-streaming-sortformer-4spk-v2.md), [Streaming Sortformer Diarizer 4spk v2.1](diar-streaming-sortformer-4spk-v2-1.md), and [Nemotron 3 Diarization](nemotron-3-diarization.md): WLK's default `sortformer` diarization path and max-speakers/arrival-order semantics build on that model line; consult those pages for DER, latency profiles, and channel behavior (**Synthesis**).[^wlk-readme]
- Complements [RealtimeSTT](realtimestt.md): RealtimeSTT is a Python VAD-gated STT library with selectable engines and a FastAPI production server, while WhisperLiveKit is a self-hosted STT server with simultaneous-speech policies and API-compatible serving; compare them on backend breadth, streaming policy, and deployment shape (**Synthesis**).[^wlk-readme]
- Evaluated with [Community-Reported Usable STT for Voice Agents](community-usable-stt-voice-agents.md): that draft's first-stable-text, partial-stability, endpointing, and per-turn-log checklist is the lens for judging WLK's SimulStreaming/LocalAgreement cadence, pause segmentation, and diff/full protocols (**Synthesis**).[^wlk-readme]
