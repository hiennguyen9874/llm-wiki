PulseVAD is an ultra-compact voice activity detector (VAD) that takes 16 kHz mono audio, computes a 64-bin log-mel spectrogram over a strictly causal 200 ms window (3,200 samples), and runs a depthwise-separable 1D CNN with 2,118 parameters. The weight payload is 2.1 KB in INT8; the shipped INT8 ONNX graph is 26.8 KB, and a standalone C header targets Cortex-M, ESP32, STM32, and Arduino. The README (a vendor capture, no revision, date, or upstream URL recorded) claims 99.3% F1 on clean speech, 0.73 ms CPU time per window, and that it is 87x smaller than Silero by file size, while admitting weaker behavior on music and noisy far-field mixes. It was built by distilling an 81,090-parameter teacher, pruned with DepGraph structured pruning, labeled by Silero VAD outputs so the data stays commercially permissive. Every number below is **Reported** by the vendor and was not reproduced.[^pulsevad-readme]

## Identity and licensing

- Self-described "commercially clean" detector "built from scratch", inspired by the kiloVAD architecture of Bauer et al., "VAD to the Bone: Ultra-Tiny Speech Activity Detection for Edge Deployment" (arXiv 2607.25870v1, INTERSPEECH 2026; paper not captured). Install: `pip install pulsevad` or `uv add pulsevad` (**Reported**).[^pulsevad-readme]
- License: MIT per the README, which links a `LICENSE` file that was not captured. Training data is described as LibriSpeech and MUSAN (both stated CC BY 4.0), with labels generated by MIT-licensed Silero VAD; the README explicitly avoids LibriVAD and AVA CC-BY-NC splits (**Reported**; **Unverified** against the license files).[^pulsevad-readme]
- The audio.cpp GGUF catalog lists a `PulseVAD-GGUF` package (`pulsevad`, F32, MIT); the README does not mention GGUF, so linking the two is by name only (**Synthesis**). See [audio.cpp GGUF Packages](audio-cpp-gguf-packages.md) and [audio.cpp Framework](audio-cpp-framework.md).

## Interface and usage

- Python API: `load_pulsevad(onnx=True, quantized=True, model_type="81k", device=...)`, `read_audio(path, sampling_rate=16000)`, `predict_window(model, chunk)` returning a speech probability in [0, 1], `get_speech_timestamps(wav, model, threshold=0.5, min_speech_duration_ms=100, min_silence_duration_ms=150)` returning sample-index segments, and `get_model_path(name)` for the bundled C header (**Reported**).[^pulsevad-readme]
- Streaming: buffer 3,200 samples (200 ms at 16 kHz), call `predict_window`, and threshold at 0.5. The model keeps no recurrent state, so there are no hidden-state tensors to manage (**Reported**).[^pulsevad-readme]
- The detector needs a 64-bin log-mel front end (pre-emphasis 0.97, z-normalization); on a microcontroller the integrator must supply an FFT plus mel filterbank, which the README says CMSIS-DSP covers (**Reported**).[^pulsevad-readme]
- Granularity is one decision per non-overlapping 200 ms window, so segment boundaries are 200 ms coarse and endpoint latency includes up to 200 ms of buffering; the README itself flags this against Silero's 32 ms sub-chunks. The `min_speech_duration_ms=100` example sits below the window size, and how sub-window durations are handled is not documented (**Observed** gap).[^pulsevad-readme]
- Reproduction: training, pruning, and evaluation run on Modal per `REPRODUCE.md` (not captured) (**Reported**).[^pulsevad-readme]

## Architecture and training recipe

Pipeline as drawn in the README: 16 kHz audio → pre-emphasis 0.97 + z-norm → 64-bin log-mel (21 frames x 64 bins) → conv1d adapter 64→16 → depthwise-separable block 1 (k=11, 16 ch) → block 2 (k=17, 16 ch) → dilated depthwise block 3 (k=29, dilation 2, 16 ch) → global average pooling → linear 16→2 → prior-bias shift of −1.40 → P(speech). The count is 44,000 MACs per 200 ms window (1.66 M for the teacher) (**Reported**).[^pulsevad-readme]

Recipe (**Reported**):[^pulsevad-readme]

1. **Teacher.** An 81,090-parameter CNN trained on LibriSpeech with synthetic room impulse responses (pyroomacoustics), synthetic wind, and MUSAN noise at −10 to +10 dB SNR. Direct training of the 2.1k net "gets stuck" and predicts noise always, which motivates distillation.
2. **Labels.** 28,539 LibriSpeech files labeled by Silero VAD with a 0.50/0.35 hysteresis state machine on a 10 ms grid.
3. **Pruning.** DepGraph dependency-graph magnitude pruning, because uniform pruning collapses below about 3k parameters.
4. **Distillation.** KL divergence with temperature scaling and cosine learning-rate decay against the frozen teacher.
5. **Prior-bias calibration.** LibriSpeech is about 78% speech, so the distilled student inherited a +1.4 logit positive prior and a 25% false-positive rate on pure noise; quantile-based shifting of the final bias lowered gated noise FPR to 3.5% (6.3% false alarm at threshold 0.5) with ROC-AUC unchanged.
6. **PTQ.** BatchNorm folded into conv weights, symmetric per-channel weight scales, per-tensor activation scales; FP32→INT8 AUC gap under 0.001.

Because the training labels are Silero outputs, the student's labels agree with Silero by construction and the README does not state what ground truth its benchmark F1 scores use; treat F1 wins over Silero cautiously (**Synthesis**, open question).[^pulsevad-readme]

Reading (**Synthesis**):

- Strength: clean near-mic speech, tiny footprint, no recurrent state, and a much lower false-alarm rate than kiloVAD. Mean F1 90.1 is a tie with kiloVAD and WebRTC (90.0) and below Silero (93.6).
- Weakness: music (33.3% FAR versus Silero 15.7%; README gives music AUC 75–80 versus Silero 90–95) and noisy far-field DEMAND mixes. Silero still wins pure-noise FPR and speech-plus-noise AUC at every row shown.
- Multilingual claim: the README says performance is "flat" across Hindi, Tamil, Malayalam, Kannada, Telugu, and English but gives no numbers, dataset, or protocol; the listed training audio is English LibriSpeech, so the claim is **Unverified**. Vietnamese is not mentioned (**Observed** gap).[^pulsevad-readme]

## Self-reported trade-offs

Advantages: 2.1 KB fits in L1 cache or MCU SRAM, pure C array weights or ONNX, noise/wind/reverb robustness from augmentation, MIT license, and zero lookahead. Disadvantages: weak on music (raise the threshold or use Silero), behind Silero on noisy far-field mean F1 (the README targets near-mic real-time communication such as calls, voice notes, and dictation), 200 ms window granularity, a lower clean-studio AUC ceiling (0.976 versus 0.988–0.990), and the mel-front-end requirement (**Reported**).[^pulsevad-readme]

## Relationships

- Peer and head-to-head subject of [Silero VAD](silero-vad.md), which this page treats as teacher-labeler and main baseline; the Silero v5/v6 measurements here are the vendor's own streaming setup, not Silero's. Also a peer of [TEN VAD](ten-vad.md), [FireRedVAD](firered-vad.md), and [Frame-VAD Multilingual MarbleNet v2.0](frame-vad-multilingual-marblenet-v2-0.md). No two pages share a benchmark, so rankings across them are not comparable (**Synthesis**).[^pulsevad-readme]
- Uses Silero VAD outputs as training labels and kiloVAD as architectural inspiration (**Reported**).[^pulsevad-readme]
- Detects speech presence only, with no end-of-turn semantics. For conversational endpointing pair it with a model from [Turn Detection Models](turn-detection-models.md). For a voice-agent loop its 200 ms input window, music weakness, and unreported Vietnamese or telephony behavior mean a Silero or TEN baseline, as in [Vietnamese Realtime Voice Agent Stack](vietnamese-realtime-voice-agent-stack.md), is the safer default until measured on in-domain audio (**Synthesis**).
- Fits where a microcontroller, wake-up gating, or sub-30 KB footprint matters, as a cheap pre-filter ahead of ASR to reduce wasted decoding (**Synthesis**).

## Contradictions

- **Silero size.** The prose calls Silero "545,000 parameters (~2.2 MB)", while the comparison tables list 462,594 parameters and 2,328 KB, and a later passage gives v5 as 545k and v6 as 309k (~1.2 MB). Which Silero build the 87x file-size ratio uses is therefore ambiguous; 2,328 KB / 26.8 KB ≈ 87 matches the table figure (**Reported**; **Synthesis**).[^pulsevad-readme]
- **Hidden width.** The architecture diagram shows a 64→16 adapter with 16-channel blocks, while the C-header listing shows `conv1d_adapter_weight[12][64][1]`, `dw_conv0_weight[12][1][11]`, and `pw_conv0_weight[8][12][1]`, which implies 12/8 channel widths. The README does not reconcile the two, and the weights were not inspected (**Observed**; **Unverified**).[^pulsevad-readme]
- **MarbleNet licensing and latency.** The README labels MarbleNet 91,000 parameters, non-commercial, and 630 ms latency; the [MarbleNet v2.0 page](frame-vad-multilingual-marblenet-v2-0.md) records a 91.5K-parameter model on 20 ms frames under the NVIDIA Open Model License described as ready for commercial use. The README likely refers to another MarbleNet version or configuration and does not name its checkpoint, so neither claim is chosen (**Reported**).[^pulsevad-readme]
- **False-alarm metrics.** "6.3% false alarm at threshold 0.5" and "3.5% gated FPR@95" describe different operating points on different sets; they are not interchangeable (**Synthesis**).[^pulsevad-readme]
