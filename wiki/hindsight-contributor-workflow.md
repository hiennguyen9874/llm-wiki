The repo's single authoritative rulebook for humans and coding agents is `CLAUDE.md` (root `AGENTS.md` is a one-line pointer to it). Key rules below are Reported from those files and were not exercised.[^claude-md]

## Pull requests and security

- **External pull requests are not accepted**; file issues or Discussions instead.[^contributing] The README still points to CONTRIBUTING.md for contributions.[^readme]
- **Vulnerabilities:** only the latest version is patched; report privately through GitHub Security Advisories (never public issues); response within 48 hours; CISA-coordinated disclosure.[^security]

## Development workflow

- Bootstrap with `./scripts/dev/setup.sh`; run services with `./scripts/dev/start.sh` (or `start-api.sh`, `start-control-plane.sh`, `start-docs.sh`).[^claude-md]
- **Lint is mandatory** after changes: `./scripts/hooks/lint.sh` (changed packages) or `LINT_ALL=1` (as CI). Python: `ruff check --fix`, `ruff format`, `ty check`; TS: `eslint`, `prettier`. Dead-code gates: `knip` (blocking in CI), vulture (advisory), ruff F401/F841. `ruff.toml`: line length 120, py311, rules E, W, F, I.[^claude-md]
- **Tests:** deterministic tests assert directly; every user-facing capability needs a blackbox story in `hindsight-system-tests/` using the real API via the Python client; LLM-behaviour tests must use a real LLM plus an independent LLM judge and never hard-assert `fact_type`. See [Benchmarks and testing](hindsight-benchmarks-and-testing.md).[^claude-md]

## Generated files and config changes

- After any endpoint change run `./scripts/generate-openapi.sh`; SDKs via `./scripts/generate-clients.sh` — clients are regenerated only at release. See [Clients](hindsight-clients-cli-embed.md).[^claude-md]
- `hindsight-integrations/coding-agents/README.md` is the single source for its `skill/SKILL.md` and docs page (`npm run skill:build`); the `hindsight-docs` skill is generated by `scripts/generate-docs-skill.sh`. See [Coding agents](hindsight-coding-agents.md).[^claude-md]
- Configuration changes touch `HindsightConfig` in `hindsight_api/config.py` (`ENV_*`, `DEFAULT_*`, `_CONFIGURABLE_FIELDS`), optionally `main.py._parse_cli_args`, the docs table in `configuration.mdx` and `.env.example`. See [Storage and configuration](hindsight-storage-and-configuration.md).[^claude-md]
- Never add "Unreleased" changelog entries.[^claude-md]

## Releases

`./scripts/release.sh <version>` bumps API, clients, CLI, control plane and Helm versions, regenerates OpenAPI and clients, updates docs version, commits, tags and pushes. Integrations release separately via `scripts/release-integration.sh` and must be listed in `VALID_INTEGRATIONS`; new ones need real tests and a CI job. See [Deployment and CI](hindsight-deployment-and-ci.md).[^claude-md]

## Relationships

Applies to every package in the [Hindsight overview](hindsight-overview.md).
