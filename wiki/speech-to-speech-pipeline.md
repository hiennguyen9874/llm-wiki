HF Speech-to-Speech (`huggingface/speech-to-speech`, PyPI `speech-to-speech`) is an Apache-2.0 low-latency modular voice-agent pipeline that cascades **VAD → STT → LLM → TTS** in per-stage threads joined by queues, defaults to Silero VAD plus Parakeet TDT STT plus an OpenAI-compatible LLM plus Qwen3-TTS, and exposes the core OpenAI Realtime GA event set over WebSocket and WebRTC with every component swappable between local, self-hosted, and hosted providers (**Reported**).[^speech-to-speech-readme]

## Identity and status

- Repository `huggingface/speech-to-speech`, PyPI `speech-to-speech`, Python 3.10+ (3.11 recommended); license Apache-2.0; stated production use as the conversation backend for thousands of Reachy Mini robots (**Reported**).[^speech-to-speech-readme]
- The LLM slot speaks OpenAI-compatible protocols, so it can point at a hosted provider, HF Inference Providers, or a vLLM or llama.cpp server for a fully local open stack; code targets Transformers and Hugging Face Hub models for easy modification (**Reported**).[^speech-to-speech-readme]
- Only placeholder secret names appear in the source (`$OPENAI_API_KEY`, `$HF_TOKEN`, `$OPENROUTER_API_KEY`, `$PROVIDER_API_KEY`); no live credential or PII is present (**Observed** by static inspection).[^speech-to-speech-readme]

## Architecture

- Four threaded stages connected by queues: (1) Voice Activity Detection for speech boundaries and turn-taking, (2) STT with optional live partial transcripts, (3) LLM generating streaming text and tool calls, (4) TTS synthesizing and streaming audio back (**Reported**).[^speech-to-speech-readme]
- Default VAD is [Silero VAD v5](silero-vad.md); default STT is Parakeet TDT (see [Parakeet TDT 0.6B V3](parakeet-tdt-0.6b-v3.md)); default TTS is Qwen3-TTS (see [Qwen3-TTS-12Hz-1.7B-CustomVoice](qwen3-tts-12hz-1.7b-customvoice.md) and [Faster Qwen3-TTS](faster-qwen3-tts.md)); default LLM path is the Responses API with `gpt-5.6-terra` (**Reported**).[^speech-to-speech-readme]
- Server implements a tested core Realtime subset, not full OpenAI Realtime equivalence: inbound `input_audio_buffer.append`, `session.update`, `conversation.item.create`, `conversation.item.truncate`, `response.create`, `response.cancel`; outbound speech start/stop, streaming transcription, audio deltas, tool calls, `response.done`; CI connects pinned `@openai/agents` `RealtimeSession` instances over stock WebSocket and WebRTC transports (**Reported**).[^speech-to-speech-readme]

## Starting configurations and hardware planning

- Three documented starting configurations, all defaulting to local Parakeet TDT STT and Qwen3-TTS output; memory figures are planning estimates for one conversation, not measured minima, varying with context length, audio length, and backend versions (**Reported**).[^speech-to-speech-readme]
- Apple Silicon fully local: `speech-to-speech local --mac-optimal-settings --model_name mlx-community/Qwen3-4B-Instruct-2507-4bit`; budget 16 GB+ unified memory; no conversation data sent to a provider; ~7.5 GB core weights (Parakeet TDT MLX, 4-bit Qwen3-4B via MLX LM, 6-bit Qwen3-TTS CustomVoice via MLX Audio) plus dependencies (**Reported**).[^speech-to-speech-readme]
- NVIDIA GPU fully local: `--device cuda --stt parakeet-tdt --llm_backend transformers --model_name Qwen/Qwen3-4B-Instruct-2507 --llm_torch_dtype float16 --tts qwen3 --qwen3_tts_backend ggml`; budget 24 GB VRAM for unquantized LLM plus speech models and caches, plus system RAM; no provider data sent; LLM weights alone ~8 GB (**Reported**).[^speech-to-speech-readme]
- Local speech with hosted LLM: `--stt parakeet-tdt --llm_backend responses-api --tts qwen3` with `$OPENAI_API_KEY`; budget ~8 GB available memory (16 GB total recommended on Mac; ~8 GB VRAM plus RAM on NVIDIA); sends transcribed text, instructions, and history to the provider while microphone audio and synthesis stay local; ~5.2 GB core speech weights on Apple Silicon (**Reported**).[^speech-to-speech-readme]
- All configurations need internet for first model downloads; hosted LLM also needs an API key and internet during conversations; offline reuse requires pre-caching (see below) (**Reported**).[^speech-to-speech-readme]
- llama.cpp pairing budgets ~8 GB for the speech pipeline alongside the LLM and runtime cache: 24 GB total unified memory on Mac or 16 GB VRAM on NVIDIA, e.g. Gemma 4 `Q4_0` (~4.6 GB) served with one 8k context, `--no-mmproj`, and reasoning off, connected via `--responses_api_base_url http://127.0.0.1:8080/v1` with matched `--model_name` alias (**Reported**).[^speech-to-speech-readme]

## Installation and optional components

- Base install in a venv with `pip install speech-to-speech`; Ubuntu needs `libportaudio2` plus `libsndfile1`; macOS versus non-macOS dependencies resolve via platform markers (**Reported**).[^speech-to-speech-readme]
- Linux Qwen3-TTS GGML backend comes from `faster-qwen3-tts[ggml]` whose default `qwentts-cpp-python` wheel targets CUDA 12.8 and `manylinux_2_39` (e.g. Ubuntu 24.04); older CUDA/glibc hosts must pre-install a matching `cu130`, `cu124`, or `cpu` wheel from the stated Hugging Face wheelhouse; `--qwen3_tts_backend torch` selects the older CUDA-graphs implementation (**Reported**).[^speech-to-speech-readme]
- Pip extras select opt-ins: `kokoro`, `pocket`, `chattts`, `omnivoice`, `faster-whisper`, `whisper-mlx`, `paraformer`, `fireredvad`, `nemo` (Parakeet Unified, Nemotron, Orukeet), `mlx-lm`; deprecated MeloTTS lives unwired in `archive/`; DeepFilterNet audio enhancement needs `numpy<2` and conflicts with Pocket TTS (`numpy>=2`), so install it manually only without Pocket TTS (**Reported**).[^speech-to-speech-readme]

## Supported components

- VAD: Silero VAD v5 (all platforms, built-in) and FireRed Stream-VAD (CUDA/CPU, `fireredvad`) (**Reported**).[^speech-to-speech-readme]
- STT: Parakeet TDT default (CUDA/CPU via nano-parakeet, Apple Silicon via MLX); Parakeet Unified, Nemotron Speech Streaming, Nemotron Streaming Farsi (via `--stt nemotron-streaming` plus model name), and Orukeet via `nemo`; Whisper via Transformers, [Faster-Whisper](faster-whisper.md), Lightning Whisper MLX and MLX Audio Whisper on Apple Silicon, Paraformer via FunASR, [Qwen3-ASR family](qwen3-asr-family.md); OpenAI-compatible `/v1/audio/transcriptions`, OpenAI Realtime transcription, and experimental vLLM Realtime transcription (**Reported**).[^speech-to-speech-readme]
- LLM: OpenAI-compatible `responses-api` (`/v1/responses`, default) and `chat-completions` (`/v1/chat/completions`); local `transformers` (CUDA/CPU) and `mlx-lm` (Apple Silicon); self-hosted vLLM or llama.cpp servers and hosted OpenAI, HF Inference Providers, and OpenRouter endpoints (**Reported**).[^speech-to-speech-readme]
- TTS: Qwen3-TTS default (GGML/CUDA on Linux, mlx-audio on macOS); Kokoro-82M; [Pocket TTS](pocket-tts.md); ChatTTS; [OmniVoice](omnivoice.md) (CUDA/Intel XPU/Apple Silicon, plus Ascend NPU via `torch_npu`); MMS TTS; OpenAI-compatible `/v1/audio/speech`; optional streaming speaker diarization via `--diarization` while upstream Transformers PR #49056 is pending (**Reported**).[^speech-to-speech-readme]
- The captured TTS handler reference lists the runtime-supported `--tts` values as `chatTTS`, `facebookMMS`, `pocket`, `kokoro`, `omnivoice`, `qwen3`, `openai`, and `supertonic`, with deprecated MeloTTS unwired in `archive/TTS`; Supertonic installs via `speech-to-speech[supertonic]`, exposes `--supertonic_tts_*` flags, 10 built-in `M1`–`M5`/`F1`–`F5` voices, and 44.1 kHz ONNX output downsampled to 16 kHz (see [Supertonic 3](supertonic-3.md)) (**Reported**).[^s2s-supporting-docs]
- The captured STT handler reference enumerates `--stt` modes `whisper`, `whisper-mlx`, `mlx-audio-whisper`, `faster-whisper`, `parakeet-tdt`, `parakeet-unified`, `nemotron-streaming`, `orukeet`, `paraformer`, `qwen3-asr`, and `openai`, plus the HTTP and WebSocket remote backends; [Qwen3-ASR family](qwen3-asr-family.md) shares one `Qwen3ASRSTTHandler` and the [Orukeet](orukeet.md) / Nemotron paths share `NemoASRSTTHandler` (**Reported**).[^s2s-supporting-docs]
- Selectors are `--stt`, `--llm_backend`, and `--tts`; only the selected backends' configuration is constructed while known inactive-backend options and JSON keys are accepted but ignored with a warning; `serve -h` shows defaults and selectors-before-`-h` shows another combination's flags (**Reported**).[^speech-to-speech-readme]

## Commands

- `serve` runs the pipeline server over OpenAI Realtime WebSocket plus WebRTC for apps and devices; `talk --url <full-realtime-url>` runs the packaged microphone/speaker client against an existing server; `local` composes both in-process over loopback for single-command use (**Reported**).[^speech-to-speech-readme]
- `serve` binds `127.0.0.1` by default and needs explicit `--host 0.0.0.0` for network exposure; `local` always binds loopback; replace `local` with `serve` and keep any separate LLM server running to attach an app or the `talk` client or the browser demo (**Reported**).[^speech-to-speech-readme]
- Packaged-client playback: the `local` client buffers 196 ms of received audio only with the OpenAI-compatible TTS backend to absorb HTTP inference gaps, and starts immediately otherwise; `--playback-buffer-ms` overrides either default (larger resists stutter but delays response start) and affects only the packaged Python client (**Reported**).[^speech-to-speech-readme]
- Packaged-client tools opt in with `talk --tool-module <module>` or `local --tool-module <module>`; the module contract and a Serper web-search example live in the Realtime Engine README; `--mode` is deprecated (`realtime` maps to `serve`, `local` maps to `local` with a warning, all other values removed) (**Reported**).[^speech-to-speech-readme]
- Default `serve` is equivalent to `--thresh 0.6 --stt parakeet-tdt --llm_backend responses-api --tts qwen3 --qwen3_tts_model_name Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice --qwen3_tts_speaker Aiden --qwen3_tts_language auto --qwen3_tts_backend ggml --qwen3_tts_non_streaming_mode True --qwen3_tts_mlx_quantization 6bit --model_name gpt-5.6-terra --chat_size 30 --responses_api_stream --enable_live_transcription`, with reasoning effort `none` by default (**Reported**).[^speech-to-speech-readme]
- Docker path needs the NVIDIA Container Toolkit; `docker compose up` starts a llama.cpp server with Gemma 4 plus the Realtime server on ports `8080` and `8765` (**Reported**).[^speech-to-speech-readme]

## Realtime API and LLM proxy

- Server logs per-response STT, LLM, first-TTS-audio, and speech-to-audio durations for supported backends including vLLM-backed STT and TTS; the response-latency guide holds the coverage matrix and measurement boundaries (**Reported**).[^speech-to-speech-readme]
- The captured response-latency guide defines this as a version-2 record with **estimated speech end to first generated audio** E2E, per-stage boundaries (`stt`, `llm`, `tts_ttfa`, `e2e`, `vad_decision_s`, `smart_status`, `hold_s`), a per-backend coverage matrix, and a non-additive overlap caveat; the full schema and definitions are compiled in [Speech-to-Speech Response Latency Instrumentation](speech-to-speech-latency-instrumentation.md) (**Reported**).[^s2s-supporting-docs]
- The captured engine reference documents the server as a FastAPI/uvicorn WebSocket-plus-WebRTC service giving each session a queue-backed `PipelineUnit`; its Realtime event surface, terminal statuses, tool-calling paths, `CancelScope` interruption model, and pinned `@openai/agents` compatibility matrix are compiled in [Speech-to-Speech Realtime Engine](speech-to-speech-realtime-engine.md), and the packaged `--stt openai`/`openai-realtime`/`vllm-realtime` and `--tts openai` delegation contracts in [Speech-to-Speech OpenAI-Compatible STT/TTS Backends](speech-to-speech-openai-compatible-backends.md) (**Reported**).[^s2s-supporting-docs]
- The command surface behind the documented flags is owned by [Speech-to-Speech CLI and Defaults](speech-to-speech-cli-and-defaults.md), compiled from the captured argument-class dataclasses; the server defaults to `127.0.0.1:8765` with `num_pipelines=1`, and the packaged browser client behavior is compiled in [Speech-to-Speech Browser Demo](speech-to-speech-browser-demo.md) (**Reported**).[^s2s-supporting-docs]
- With `--enable_llm_proxy`, the realtime server also exposes its configured remote LLM as a plain OpenAI-compatible endpoint concurrent with voice and never interrupted by new speech: `POST /v1/chat/completions` for `chat-completions`, `POST /v1/responses` for `responses-api`; requests are stateless, `model` is overwritten with `--model_name`, and the server-held upstream key never reaches clients (**Reported**).[^speech-to-speech-readme]
- The proxy performs no authentication or throttling of its own, is off by default, requires a remote backend, and answers 501 otherwise; enable it only on a trusted network or behind a gateway that owns access control (the s2s-endpoint replica pattern checks the API key against the session HF token and rate-limits per user) (**Reported**).[^speech-to-speech-readme]

## LLM backend selection

- The LLM is called the most compute-intensive and highest-latency stage, where one large-model forward pass can dominate end-to-end response time (**Reported**).[^speech-to-speech-readme]
- `responses-api` and `chat-completions` share the `--responses_api_*` connection flags and differ only by path (`/v1/responses` versus `/v1/chat/completions`); documented base URLs and keys cover OpenAI defaults, HF router (`https://router.huggingface.co/v1`), OpenRouter, local vLLM (`http://localhost:8000/v1`), and local llama.cpp (`http://127.0.0.1:8080/v1`) (**Reported**).[^speech-to-speech-readme]
- Prefer `chat-completions` when a provider ignores `chat_template_kwargs.enable_thinking` on the Responses path and needs `--responses_api_reasoning_effort none`, or when a server's Responses streaming tool-call path is unreliable while its Chat Completions tool-call streaming is solid (reported for some vLLM builds) (**Reported**).[^speech-to-speech-readme]
- Direct audio input uses `--stt none --llm_backend chat-completions` to send each completed VAD segment to an audio-capable model; it is not supported with `responses-api`; the default `gpt-5.6-terra` accepts text and image but not audio, so `--model_name` must name an audio-capable model; input-audio encoding is chosen with `--responses_api_audio_content_type input_audio` (embedded WAV base64, default) or `audio_url` (base64 data URL) (**Reported**).[^speech-to-speech-readme]

## Endpointing and turn-taking

- VAD tuning flags include `--thresh`, `--min_speech_ms`, `--min_speech_continuation_ms` (hysteresis for speech continuing a reopenable soft-ended uncommitted turn; recommended pairing `384`/`192`), `--min_silence_ms` (default 64 ms), `--short_segment_merge_ms`, `--speculative_reopen_ms` (800 ms default), and `--unanswered_reopen_ms` (clamped to at least `--smart_turn_max_wait_ms` when Smart Turn is on) (**Reported**).[^speech-to-speech-readme]
- Smart Turn v3.2 validates Silero end-of-speech decisions from content and prosody: complete turns start STT/LLM work immediately and use the 800 ms speculative reopen grace before committing output; incomplete turns wait `--smart_turn_incomplete_delay_ms` (600 ms default) before STT/LLM work while output stays gated by `--smart_turn_max_wait_ms` (2 s default); resumed speech reopens the turn as a newer revision, re-emits accumulated audio, and discards prior uncommitted work (**Reported**).[^speech-to-speech-readme]
- The turn tracker owns `LISTENING`, `SOFT_ENDED`, `ANSWERING`, and `CLOSED` ordering; VAD supplies boundaries and Smart Turn timing while the tracker decides reopening; the unanswered reopen cap uses streamed-audio time so push-to-talk silence without audio does not advance it, while processing and output holds use wall-clock deadlines; starting a newer turn drops older uncommitted work but accepted output may finish (**Reported**).[^speech-to-speech-readme]
- Response-to-input ownership: each response belongs to its generation input, recorded on conversation items and accepted tool calls; a tool follow-up keeps its originating turn unless a later user message reassigns it, or moves to a newer closed turn so a late tool result is still spoken; untagged client input stays untagged and a response cannot borrow identity from speech still being recorded; these records do not control turn state, reopening, or deadlines (**Reported**).[^speech-to-speech-readme]
- The server holds `input_audio_buffer.speech_stopped` and the final transcription while a turn can reopen (resumed speech keeps the same open item with continuing live deltas); on commit the client receives one stop, one buffer commitment, the created user item, and one final transcript; transcription failure reports stop plus failure after the grace ends (**Reported**).[^speech-to-speech-readme]
- Smart Turn is enabled by default for server sessions and the packaged local client via the quantized CPU runtime; the v3.2 CPU checkpoint downloads on first use, with `--smart_turn_model_path` for an explicit local checkpoint and `--no_smart_turn` to disable; `--smart_turn_threshold` defaults to `0.5` with higher values favoring the longer speculative grace on ambiguous pauses (**Reported**).[^speech-to-speech-readme]

## Multilingual behavior

- Language coverage depends on the chosen STT and TTS backends, not the pipeline: Parakeet TDT covers 25 European languages; Whisper variants depend on checkpoint; Paraformer defaults Chinese-oriented; Qwen3-TTS is multilingual with `--qwen3_tts_language auto`; Kokoro, ChatTTS (English/Chinese), MMS (broad), OmniVoice (600+ languages with cloning/design/auto), Supertonic (32 languages), Pocket TTS (English, French, German, Portuguese, Italian, Spanish), and OpenAI-compatible endpoints depend on server/model (**Reported**).[^speech-to-speech-readme]
- Pair STT, LLM, and TTS so all cover the target language; by default the TTS language code comes from the user transcription, while `--detect_llm_output_language` instead detects each assistant chunk via a warmed Lingua detector (short text under 20 characters, or under four CJK characters, and ambiguous text fall back to the last detected assistant language, else TTS uses its own auto/default to avoid delaying speech); a Realtime session language (`session.audio.input.transcription.language`) pins STT while TTS prefers the confidently detected assistant language, falling back to the session language when text is too short, ambiguous, or unsupported (**Reported**).[^speech-to-speech-readme]
- Parakeet TDT auto-selects decoding language: `--parakeet_tdt_language` is accepted for compatibility but does not constrain decoding, and the reported language is Lingua-inferred from the finished transcription when possible (short/inconclusive text reports unknown); `--language` belongs to Whisper backends (`auto` or a code such as `zh`); other backends have their own flags (**Reported**).[^speech-to-speech-readme]
- `--enable_lang_prompt` (off by default) appends a per-turn instruction such as asking for a French reply and works independently of assistant-language detection; `--qwen3_tts_language german` style overrides force synthesis language (**Reported**).[^speech-to-speech-readme]

## TTS notes: OmniVoice, Pocket, and logging

- OmniVoice needs its extra plus a reference clip and transcript (e.g. `--tts omnivoice --omnivoice_device cuda --omnivoice_ref_audio /path/to/reference.wav --omnivoice_ref_text "..."` with `mps`/`xpu`/`npu` device variants); the handler converts 24 kHz float output to 16 kHz `int16` blocks but exposes no incremental audio through `generate()`, so the first block waits for the full utterance; its code is Apache-2.0 but weights are CC-BY-NC (non-commercial) and cloning requires authorization and consent with no impersonation, fraud, scams, or illegal use (**Reported**).[^speech-to-speech-readme]
- Pocket TTS example is `--tts pocket --pocket_tts_voice jean --pocket_tts_device cpu` with presets `alba`, `marius`, `javert`, `jean`, `fantine`, `cosette`, `eponine`, `azelma`, plus custom files or Hugging Face paths (**Reported**).[^speech-to-speech-readme]
- Logs are content-free by default (transcript-bearing records report character counts, not text, because service managers, containers, and aggregators retain logs); `--log_transcripts` (client spelling `--log-transcripts`/`--log_transcripts`) includes full user and assistant transcripts with a startup warning (**Reported**).[^speech-to-speech-readme]
- Shared LLM flags are unprefixed (`--model_name`, `--chat_size`); backend-specific flags use `responses_api_` for remote backends and `llm_` for local backends; per-handler generation overrides use `<prefix>_gen_` (e.g. `--stt_gen_max_new_tokens 128`, `--llm_gen_temperature 0.7`) (**Reported**).[^speech-to-speech-readme]
