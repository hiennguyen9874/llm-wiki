VieNeu-TTS is an on-device Vietnamese text-to-speech family by Pham Nguyen Ngoc Bao, trained on 10,000+ hours of bilingual data, whose latest open-source release v3 Turbo synthesizes 48 kHz audio with 25 preset voices, instant voice cloning from a 3–8 s clip, experimental inline emotion cues, batched generation, LoRA fine-tuning, and real-time frame-level streaming behind an OpenAI-compatible API, reporting about 115 ms time to first audio with 16 concurrent streams on a single RTX 3060 and about 2x real-time on a plain CPU (**Reported**).[^vieneu-tts-repo]

## Model identity and release lineage

- Title is `VieNeu-TTS`; author is Pham Nguyen Ngoc Bao; repository is `https://github.com/pnnbao97/VieNeu-TTS`; Hugging Face publisher is `pnnbao-ump` (v1, v2, v3-Turbo checkpoints); v3 Turbo architecture was designed and trained from scratch on about 10,000 hours of English–Vietnamese speech (dataset `pnnbao-ump/VieNeu-TTS-10k-ENVI`), stated to be an original design and not a fine-tune, distillation, or adaptation of an existing TTS model, with codec `MOSS-Audio-Tokenizer-Nano` and phonemizer `sea-g2p`; stated license is Apache 2.0 (**Reported**).[^vieneu-tts-repo][^vieneu-v3-turbo-card]
- **v3 Turbo is the current default and latest open-source release**; **v4** delivers near-original cloning fidelity but is proprietary, will not be open-sourced, and is available only through the VieNeu API / vieneu.io; the full **v3** server release (finalized quality, stable emotion control, more voices) is coming soon; the mobile SDK is pending (**Reported**).[^vieneu-tts-repo]
- **v3 Nano (preview)** is a 48M-parameter flow-matching ONNX model for weak CPUs and edge devices: CPU-only, torch-free, 24 kHz, 11 preset voices plus cloning, no frame-level streaming, noticeably lower quality especially on English and code-switched English-Vietnamese text (**Reported**).[^vieneu-tts-repo]
- Deprecated lineage kept only for existing deployments: v2 (plus CPU/GGUF and Turbo GGUF variants) and v1; new projects should use v3 Turbo (and v3 once released) (**Reported**).[^vieneu-tts-repo]
- Early v1/v2-era pair behind that deprecated lineage: **VieNeu-TTS (0.5B)**, an enhanced fine-tune of the NeuTTS Air architecture (`neuphonic/neutts-air`) for maximum stability, and **VieNeu-TTS-0.3B**, trained from scratch for about 2x faster inference and ultra-low latency, both trained on the `VieNeu-TTS-1000h` dataset (card frontmatter also names `VieNeu-TTS-140h`); stated license is Apache 2.0 (**Reported**).[^vieneu-tts-early]
- Early packaging ladder: full PyTorch `VieNeu-TTS` (GPU/CPU, very fast with LMDeploy), PyTorch `VieNeu-TTS-0.3B` (GPU/CPU, ultra-fast 2x), and `VieNeu-TTS-0.3B-q4-gguf` GGUF Q4 (CPU/GPU, extreme speed 2x at reduced quality) on 5/4/3-star qualitative ratings (**Reported**).[^vieneu-tts-early]

## Capabilities

- 25 preset voices across North, Central, and South regions with diverse genders and characters; 10 editors' picks are recommended starting points (Adam bua, Truc Ly, Thien Minh, Mai Anh, Hai Dang as default, Thuy Dung, Thien Tam Duc, Ngoc Huyen, Quang Son, Ngoc Tran); enumerated without reference clips via `list_preset_voices()` (**Reported**).[^vieneu-tts-repo]
- Versioned roster note: the SDK v3.7.1 card snapshot documents a 23-voice roster (North/Central/South, both genders, several reading characters) defaulting to `Minh Quân`, with `list_preset_voices()` authoritative at the installed version; earlier revisions shipped fewer voices under partly different names (3.3.0: 20 voices, default `Adam`), so pin the SDK version when the exact roster matters (**Reported**).[^vieneu-v3-turbo-card]
- Early 6-voice preset set (supplanted by the 25-voice v3 set): Binh and Tuyen (male, North), Nguyen (male, South), Huong and Ngoc (female, North), Doan (female, South) (**Reported**).[^vieneu-tts-early]
- Early cloning threshold was 3–5 s of reference audio on all variants including GGUF, versus 3–8 s with auto-denoise/trim on v3 Turbo; early zero-shot call passes `ref_audio` plus `ref_text` transcript alongside `text` (**Reported**).[^vieneu-tts-early]
- Instant voice cloning from a 3–8 s reference clip with automatic denoising and trimming to at most 8 s; keep `denoise=True` unless the clip is already clean; `add_voice` enrolls a reusable named voice, `save_voices` persists it, and `denoise` cleans a clip standalone at 44.1 kHz mono (**Reported**).[^vieneu-tts-repo]
- Reading style follows the reference voice itself (speaker embedding plus reference codes); the `style` argument on `infer`, `infer_stream`, `infer_batch`, and `add_voice` is deprecated and ignored but still accepted for backward compatibility (**Reported**).[^vieneu-tts-repo]
- Experimental inline emotion and non-verbal cues dropped directly into text: `[cuoi]` (chuckle), `[tho dai]` (sigh), `[hang giong]` (clear throat) (**Reported**).[^vieneu-tts-repo]
- Batched generation up to batch size 32 via `infer_batch`, including a multi-speaker Conversation mode that batches the whole script regardless of speaker; a single long `infer` also auto-batches its own chunks; on CPU batching still runs but sequentially with no throughput gain (**Reported**).[^vieneu-tts-repo]
- LoRA fine-tuning teaches one voice (about 10–30 minutes of clean single-speaker audio per LoRA) for a tighter-than-cloning match, a specific reading style, or domain reading; only a few million parameters train so about 6 GB GPU suffices; the merged model packs its speaker embedding so no reference audio is needed and keeps the v3 Turbo API on the PyTorch/GPU backend (**Reported**).[^vieneu-tts-repo]
- Stability tip from the v3 Turbo card: a temperature around 0.8 gives the most stable result; higher values add expressiveness but can be less stable (**Reported**).[^vieneu-v3-turbo-card]

## Runtime and SDK

- `vieneu` SDK defaults to `Vieneu(mode="v3turbo")` at 48 kHz; CPU path is torch-free ONNX Runtime, GPU path auto-switches to PyTorch with automatic batching under the same API; `Vieneu(mode="v3nano")` selects Nano at 24 kHz (**Reported**).[^vieneu-tts-repo]
- Early SDK default was `Vieneu()` on `0.3B-Q4 GGUF` for CPU; shared call shape `list_preset_voices()` / `get_preset_voice(id)` / `infer(text, voice=...)` / `save(spec, path)` / `close()`, with early install via `pip install vieneu` (Linux/macOS) or `pip install vieneu --extra-index-url https://pnnbao97.github.io/llama-cpp-python-v0.3.16/cpu/` on Windows to avoid llama-cpp build errors, and Web UI via `git clone` plus `uv sync` plus `uv run vieneu-web` (**Reported**).[^vieneu-tts-early]
- CPU precision defaults to fp32 for maximum fidelity; `precision="int8"` is about 1.6x faster (RTF about 0.35) and 4x smaller but requires VNNI (AVX-512 VNNI / AVX-VNNI), and can produce garbled audio on older CPUs; `precision` is ignored on GPU (**Reported**).[^vieneu-tts-repo]
- GPU execution fuses each audio frame (acoustic decoder plus sampling plus repetition penalty plus backbone step) into one CUDA graph without `torch.compile` or a C++ toolchain; the first call per batch size pays about 0.5 s for graph capture, servers can call `warm_fused()` at startup, and `VIENEU_FUSED_FRAME=0` restores the plain loop (**Reported**).[^vieneu-tts-repo]
- Streaming via `infer_stream` yields `np.float32` at 48 kHz chunk by chunk; calling it from many threads is the intended multi-listener GPU pattern with ceiling `Vieneu(max_streams=16)`; Nano's `infer_stream` yields one finished chunk at a time rather than frame-level streaming (**Reported**).[^vieneu-tts-repo]
- Install paths: minimal CPU/macOS via `uv sync` plus `uv run vieneu-web` (UI at `http://127.0.0.1:7860`), or `pip install vieneu`; GPU via `uv sync --extra cuda`, or CUDA torch 2.8.0 plus torchaudio 2.8.0 from the cu128 index with pinned `transformers==4.57.6` then `pip install vieneu[cuda]`; Windows standalone installer is at vieneu.io with a macOS installer pending (**Reported**).[^vieneu-tts-repo]
- Nano knobs: `steps` (Euler steps, 16 default; 8 is about 2x faster but rougher, paired with `sway=-1`), `cfg` (3.0 default; `cfg=0` halves compute but hurts intelligibility), plus `speed`, `seed`, `threads` (**Reported**).[^vieneu-tts-repo]
- Fine-tune commands: `uv sync --extra finetune`, `finetune/prepare_dataset.py --dataset-dir finetune/dataset`, `finetune/train_lora.py --data finetune/dataset/train.parquet --run my_voice --merge`, `finetune/make_voice.py --audio ref.wav --name "My voice" --out finetune/output/my_voice/merged`, then `Vieneu(mode="v3turbo", backbone_repo="finetune/output/my_voice/merged")` (**Reported**).[^vieneu-tts-repo]

## Serving API and Docker

- `apps/openai_speech.py` serves `POST /v1/audio/speech` like OpenAI's TTS endpoint (`pcm`/`wav`, chunked body or SSE), so the OpenAI SDK, Pipecat, LiveKit Agents, and Vercel AI SDK work by changing `base_url`; endpoints also include `GET /v1/models`, `GET /v1/voices`, `POST /v1/voices` (clone from upload), and `GET /health` (**Reported**).[^vieneu-tts-repo]
- Concurrency is capped per backend (`VIENEU_MAX_STREAMS`, default 16 on GPU and 1 on CPU) with a small queue and HTTP 429 beyond it; every reserved slot adds about 2.5 ms to each codec call, so `max_streams` should match real load (**Reported**).[^vieneu-tts-repo]
- Launch via `uv run python -m apps.openai_speech` (auto-detects GPU/CPU) or Docker Compose profiles `api-gpu` / `api-cpu` on port 8000; Web UI in Docker via profiles `gpu` / `cpu` on port 7860; production builds are documented in `docs/Deploy.md` with streaming method in `docs/streaming.md` (**Reported**).[^vieneu-tts-repo]
- Legacy v2 LMDeploy server plus `remote` SDK mode are deprecated and kept only for existing v2 deployments (GPU Docker `pnnbao/vieneu-tts:latest` with `--tunnel` bore tunnel on port 23333); v3 Turbo is not served by that container and fine-tuned v3 Turbo models load through the SDK instead (**Reported**).[^vieneu-tts-repo]
- Early remote pattern behind that legacy mode: deploy `docker run --gpus all -p 23333:23333 pnnbao/vieneu-tts:serve --model pnnbao-ump/VieNeu-TTS --tunnel`, then connect with `Vieneu(mode='remote', api_base='http://your-server-ip:23333/v1', model_name='pnnbao-ump/VieNeu-TTS')`; the client stays lightweight by loading only a small codec locally, encoding reference audio locally and sending codes to the server (**Reported**).[^vieneu-tts-early]

## Benchmarks

- Measurement basis stated in the source: RTX 3060 12 GB with Intel Core i5 12th gen (6 P-cores, 12 threads) on Windows 11, torch 2.8 plus cu128 (bf16), ONNX Runtime 1.24 (fp32/int8, 6 threads), `vieneu` 3.8.x, September 2026; RTF is generation time divided by audio duration with lower faster and below 1 faster than real-time; TTFA is time to the first audio chunk when streaming; reproduction via the SDK snippets and `examples/openai_speech_client.py --bench N` (**Reported**).[^vieneu-tts-repo]
- Throughput: GPU batched RTF 0.011–0.02 (e.g. 30 sentences / 130 s audio in 1.5–2.3 s); GPU single sentence RTF 0.10 (3.5 s in 0.36 s, launch-bound); CPU Turbo fp32 RTF 0.55–0.62; CPU Turbo int8 RTF 0.35–0.37; CPU Nano 16-step RTF 0.22; CPU Nano 8-step RTF 0.11; GPU is about 25–50x faster than CPU on bulk work but only about 5x on a single short sentence (**Reported**).[^vieneu-tts-repo]
- Streaming: GPU 1 stream TTFA about 115 ms (106 ms over HTTP) at RTF 0.49; 8 streams 164 ms at RTF 0.56; 16 streams 185 ms median (339 ms max when all start at once; 134 ms for a request arriving while 15 play) at RTF 0.59; 32 streams about 450 ms at RTF 0.93; CPU fp32 260–400 ms TTFA at RTF 0.55–0.61 with two concurrent streams stalling (RTF 1.19); CPU int8 140–195 ms TTFA at RTF 0.35 with two streams at 0.58–0.67 (**Reported**).[^vieneu-tts-repo]
- Operating notes: a stream lives only while a reply plays so 16 streams serve roughly 45–80 active voice-chat users; VRAM peaks at 1.1 GB at 16 streams; after idle seconds the GPU parks at low clocks and the first request pays 100–300 ms extra (mitigated with locked clocks); per-source pointer `docs/streaming.md` holds other-GPU estimates and full method (**Reported**).[^vieneu-tts-repo]
- Nano resource footprint on the same desktop CPU: about 3x faster than Turbo fp32 (Nano RTF 0.11–0.22 versus Turbo fp32 0.62 and int8 0.37), 282 MB download, about 3 s load time (**Reported**).[^vieneu-tts-repo]

## Licensing and use rights

- Apache-2.0 is stated to cover all shipped artifacts: `model.safetensors`, ONNX exports, configs and tokenizers, and bundled preset-voice assets (speaker embeddings plus reference codes in `voices_v3_turbo.json`); third-party components `MOSS-Audio-Tokenizer-Nano` (Apache-2.0) and `sea-g2p` keep their own notices on redistribution (**Reported**).[^vieneu-v3-turbo-card]
- Bundled preset voices are stated to be usable in commercial and monetized content (voice-over, videos, products, services) with no additional license or fee; the speakers or rightsholders behind the shipped preset-voice assets are stated to have granted rights and consent for AI training and synthetic speech generation (**Reported**).[^vieneu-v3-turbo-card]
- Training-corpus pipeline is stated to be undisclosed and the `VieNeu-TTS-10k-ENVI` dataset gated; the consent and commercial-use confirmations cover only the shipped preset voices and released weights, not user-supplied cloning references (**Reported**).[^vieneu-v3-turbo-card]
- Cloning responsibility stays with the user: do not clone real people without permission and do not use the model to impersonate, defraud, or produce misleading content (**Reported**).[^vieneu-v3-turbo-card]
