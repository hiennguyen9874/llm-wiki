Speculators is an external `vllm-project` library for accelerating LLM inference through speculative decoding by training efficient draft models that deploy directly into vLLM[^speculators].

## Features

- Offline training-data generation using vLLM: generates hidden states with vLLM and saves samples to disk for draft-model training[^speculators].
- End-to-end training of single- and multi-layer draft models for both non-MoE and MoE models[^speculators].
- Standardized, extensible Hugging Face-compatible format for speculative models, plus tools to convert external research repositories into the Speculators format[^speculators].
- Seamless vLLM integration for direct deployment with low-latency, production-grade inference and minimal overhead[^speculators].

## Mechanism

Autoregressive generation emits one token per full target-model forward pass, leaving GPU compute underutilized on memory-bound decoding[^speculators]. Speculative decoding uses a smaller, faster draft model — often a single transformer layer — to predict multiple tokens ahead, then verifies those proposals in parallel with the primary model[^speculators].

Verification preserves target-model output: accepted tokens are exactly those the target would have produced under the same sampling configuration, while rejected draft tokens are discarded and regenerated by the target model[^speculators].

## Benefits

- Reduced latency: about 2–3× faster generation for interactive use such as chatbots and code assistants[^speculators].
- Better GPU utilization: converts latency- and memory-bound decoding into compute-bound parallel verification[^speculators].
- No quality loss: same sampling-configuration output as the target model alone[^speculators].
- Cost efficiency: more requests served per GPU by shortening hardware occupancy per request[^speculators].

Speculators is most valuable for latency-sensitive, real-time workloads such as conversational AI, interactive coding assistants, and streaming text generation[^speculators].

## Speculators 0.6.0 MTP support

Version 0.6.0 adds FastMTP-style fine-tuning for verifiers that already ship a native MTP head (Qwen3-Next and Qwen3.5 including MoE): `MTPConverter` extracts native `mtp.*` weights, `MTPDraftModel` trains the single head recursively with exponential-decay weighting, and the stitcher returns `mtp.*` keys for standard `method: mtp` serving[^fastmtp]. It is the lightest training path because it reads only the verifier's last-layer hidden states, and it suits domain specialization of a general-data shipped head; verifiers without MTP heads should use EAGLE-3, DFlash, or P-EAGLE instead — see [vLLM FastMTP Fine-Tuning](vllm-fastmtp-fine-tuning.md)[^fastmtp].

## Speculators 0.6.0 P-EAGLE support

Version 0.6.0 also ships P-EAGLE parallel drafting, which predicts K tokens in one forward pass through `PEagleDraftModel` inheriting from `Eagle3DraftModel`, with COD sampling, learnable mask token plus `mask_hidden`, unfrozen embeddings, and flex-attention masking[^peagle]. The end-to-end path covers data preparation, vLLM hidden-state extraction, training, evaluation, and direct `vllm serve` deployment of the best checkpoint[^peagle] — see [vLLM P-EAGLE Speculative Decoding](vllm-peagle-speculative-decoding.md)[^peagle].
